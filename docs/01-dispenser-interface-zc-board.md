# การติดต่อหัวจ่าย: บอร์ด ZC-C / ZC-22222 (True Supply)

เอกสารเฉพาะส่วน **Dispenser Interface** — พักเรื่อง ATG ไว้ก่อน
เป้าหมาย: รับยอดขาย (read) และสั่งจ่ายน้ำมัน (control) จากตู้จ่ายจีนที่ใช้อยู่

---

## 1. ระบุฮาร์ดแวร์ที่มี

| รายการ | ค่า |
|---|---|
| ผู้จำหน่ายในไทย | บริษัท ทรู ซัพพลาย จำกัด — 155 ม.7 สุรศักดิ์ ศรีราชา ชลบุรี 20110 |
| โทร | 038-048-328 / 061-779-9988 |
| บอร์ดรุ่นใหม่ | `ZC-C V1.4` , P/N `ZC-C-C-01 WXL20200223 V3.2` (ชุดคอม MODEL C) |
| บอร์ดรุ่นเก่า | `ZC-22222` (ใช้ IC คู่ ZC-2 แยกฝั่ง A/B) |
| MCU | ตระกูล **STC (8051-compatible)** — ยืนยันจาก programmer `STC U8W-Mini` ที่แถมมา |
| รองรับ | 2 ด้าน (A/B) ต่อ 1 บอร์ด = 2 หัวจ่าย / 2 จอ / 2 pulser / 2 totalizer |

### 1.1 ขั้วต่อบนบอร์ด (จากภาพและ legend)

| ฟังก์ชัน | ZC-22222 | ZC-C V1.4 |
|---|---|---|
| Pulser (นับปริมาตรจากมาตรวัด) | `PULSER` ×2 | `PULSER-1` / `PULSER-2` |
| Totalizer (มิเตอร์สะสมกลไก) | `TOTALIZER` ×2 | `TOTALIZER-1` / `TOTALIZER-2` |
| Nozzle switch (สวิตช์คันโยก) | ×2 | (บนบอร์ด) |
| Motor & Valve (big/small valve) | ×2 | `QJH-1` / `QJH-2` |
| Display / Keyboard | ×2 | `DISPLAY-1` / `DISPLAY-2` / `KEYBOARD-2` |
| Printer | — | `PRINTER-1` / `PRINTER-2` |
| **สื่อสาร** | **RJ45 (silkscreen RS485)** | **Terminal เขียว 4 ขา (ขวาล่าง)** |
| ไฟเลี้ยง | 8V (display+main 5V), 12V (nozzle+totalizer), Battery | เหมือนกัน |
| ตั้งค่า | — | DIP `K1` (2 pos) + `SETUP SW` (2 pos) |

### 1.2 หมายเหตุจากป้าย legend (ภาพขั้วต่อ 17 จุด)

```
 1. Key board A          10. Totalizer counter B
 2. Key board B          11. Nozzle switch B
 3. Display board B      12. Nozzle switch A
 4. Display board A      13. Pulser input A
 5. Battery              14. Pulser input B
 6. Print communications 15. Motor and valve control signal
 7. Display 8V / main 5V 16. "RS 490"   ← ไม่มีมาตรฐานชื่อนี้
 8. Nozzle 12V           17. RS 485     ← ช่องทางที่เราจะใช้
 9. Totalizer counter A
```

⚠️ **`RS 490` เป็นการพิมพ์ผิดแน่นอน** — น่าจะเป็น `RS-232` หรือ `RS-422`
ตรวจง่าย ๆ ด้วยมัลติมิเตอร์ขณะบอร์ดจ่ายไฟ (วัดเทียบ GND):
- ประมาณ **±9 ถึง ±12 V** และมีแค่ TX/RX/GND → **RS-232**
- ประมาณ **0–5 V แบบ differential 4 เส้น** (TX+/TX−/RX+/RX−) → **RS-422**
- **0–5 V differential 2 เส้น** → RS-485 อีกพอร์ต

`6. Print communications` = พอร์ตปริ้นเตอร์สลิป — **เก็บไว้เป็นแผนสำรอง**
ถ้า RS-485 ใช้ไม่ได้ ยังดักอ่านข้อความสลิป (ลิตร/ราคา/ยอดเงิน) จากพอร์ตนี้ได้

## 2. ประเมินสถานการณ์แบบตรงไปตรงมา

**ข่าวดี**
- บอร์ดมี RS-485 มาให้แล้ว → ผู้ผลิตออกแบบมาให้ต่อ POS/controller อยู่แล้ว
- **ไม่ต้องแตะ pulser, ไม่ต้องแกะซีลมาตรวัด** = ถูกกฎหมาย ปลอดภัย
- บอร์ดคุม motor/valve เอง → ถ้าคุยโปรโตคอลได้ จะสั่งจ่าย (authorize/preset) ได้ด้วย

**ข่าวร้าย**
- โปรโตคอลของบอร์ดตระกูล ZC **ไม่เปิดสาธารณะ** และระบุจากรูปถ่ายไม่ได้
- บอร์ดจีนหลายรุ่นตั้งค่าให้ emulate โปรโตคอลอื่นได้ (Gilbarco/Censtar/Tatsuno) — ต้องถามผู้ขาย

**สรุป:** ต้องรู้โปรโตคอลก่อน ถึงจะเขียนโค้ดได้ — เส้นทางเรียงตามความคุ้มค่าอยู่ข้างล่าง

## 3. ขั้นที่ 0 — โทรถาม True Supply (ทำก่อนอย่างอื่นทั้งหมด)

ROI สูงที่สุด: โทร 10 นาที อาจประหยัดงาน reverse engineering 1–2 เดือน

**ขอ 5 อย่างนี้**

1. **เอกสาร RS-485 communication protocol** ของบอร์ด `ZC-C V1.4` (ภาษาจีนก็รับ)
2. **ชื่อโปรโตคอล** — ถามตรง: *"บอร์ดนี้ต่อกับ forecourt controller / ระบบ POS ยี่ห้อไหนได้บ้าง
   หรือ emulate โปรโตคอลอะไรได้ (Gilbarco / Censtar / Tatsuno)"*
3. **Baud rate + parity + วิธีตั้ง pump address** (ตั้งที่ DIP `K1`, `SETUP SW` หรือในเมนู setup?)
4. **พารามิเตอร์เปิดโหมดออนไลน์** — บอร์ดจีนแทบทุกตัวมีค่า `联机/单机` (online / standalone)
   **ถ้าไม่เปิด RS-485 จะเงียบสนิท — นี่คือสาเหตุอันดับ 1 ที่คนต่อไม่ติด**
5. **Pinout ของ terminal เขียว 4 ขา** (เส้นไหน A / B / GND / อะไรอีกเส้น)

คำถามเสริมที่มีประโยชน์:
- มีคู่มือเข้าเมนู setup ไหม (กดปุ่มอะไร ต้องสับ `SETUP SW` ไหม)
- ระยะสาย RS-485 สูงสุดที่รองรับ, ต้องใส่ terminator 120Ω ไหม
- ถ้าเปลี่ยนบอร์ดใหม่ ต้องแจ้งสำนักชั่งตวงวัดมาตรวจซ้ำไหม

## 4. ขั้นที่ 1 — ดักฟัง (listen-only) ถ้าไม่ได้เอกสาร

> **ห้ามเดาแล้วยิงคำสั่งมั่ว** — เสี่ยงบอร์ดค้างกลางการจ่ายน้ำมัน
> ขั้นนี้ต่อขนานอย่างเดียว ไม่ส่งข้อมูลออกสาย → ปลอดภัยกับตู้ที่ให้บริการอยู่

### 4.1 อุปกรณ์ที่ต้องซื้อ (~1,500 บาท)

| อุปกรณ์ | ราคา | หมายเหตุ |
|---|---|---|
| USB↔RS-485 **แบบ isolated** (FT232/CH340 + ADUM1201) | 400–800 ฿ | อย่าเอาตัว 50 บาทที่ไม่มี isolation |
| Logic analyzer 8ch (Saleae clone) | 350 ฿ | วัด baud, ดู pulser / nozzle switch |
| ตัวต้านทาน 120Ω, สายชีลด์คู่บิด (STP) | 200 ฿ | terminator + สายสัญญาณ |
| มัลติมิเตอร์ | มีแล้ว | เช็คว่า pin 16 เป็น RS-232 หรือ RS-422 |

### 4.2 การต่อ

```
   บอร์ด ZC-C                       ตู้ควบคุม (safe area)
   terminal เขียว
     A ──────────────────────────────┬── USB↔RS485 (A)
     B ──────────────────────────────┼── USB↔RS485 (B)
   GND ──────────────────────────────┴── USB↔RS485 (GND)   ← ต้องต่อ GND ด้วย
                                     │
                                    120Ω (ปลายสาย)
```
- ต่อ **ขนาน** กับ POS เดิม (ถ้ามี) — RS-485 เป็น multi-drop ต่อฟังได้
- shield ลงกราวด์ **ปลายเดียว** ฝั่ง safe area
- ไม่เดินร่วมท่อกับสายไฟกำลัง
- ถ้ายาวเกิน 100 ม. หรือข้าม building ให้ใส่ RS-485 repeater/isolator

### 4.3 ขั้นตอนจับข้อมูล

```bash
pip install pyserial

# 1) ไม่รู้ baud → สแกนก่อน (ให้ตู้จ่ายทำงานปกติระหว่างสแกน)
python3 tools/rs485/sniffer.py --port /dev/ttyUSB0 --scan

# 2) จับข้อมูล พร้อมฝัง marker
python3 tools/rs485/sniffer.py --port /dev/ttyUSB0 --baud 9600 --framing 8N1 \
        --out capture_01.jsonl
```

ระหว่างจับ ให้พิมพ์คำอธิบายสิ่งที่ทำหน้าตู้จ่ายแล้วกด Enter (ฝัง marker ลงไฟล์)
**สคริปต์ทดสอบที่ควรทำตามลำดับ** — ทำช้า ๆ เว้นช่วง 5 วินาทีระหว่างขั้น:

```
[idle 30 วินาที]              ← ดู polling frame ตอนไม่มีอะไรเกิดขึ้น
ยกหัวจ่าย A
วางหัวจ่าย A                   ← เทียบ 2 เฟรมนี้ = หา nozzle status bit
ยกหัวจ่าย A
จ่าย 1.00 ลิตร ราคา 38.44 ยอด 38.44
วางหัวจ่าย A
ยกหัวจ่าย B                    ← หา address / side ที่ต่างกัน
วางหัวจ่าย B
จ่าย 5.00 ลิตร                 ← เทียบกับ 1.00 = ยืนยันตำแหน่ง field ลิตร
เปลี่ยนราคาเป็น 39.00 (ถ้าทำได้)
```

**จดตัวเลขจริงที่จอแสดง ทุกครั้ง** — ลิตร / ราคา/ลิตร / ยอดเงิน / เลข totalizer
ตัวเลขพวกนี้คือ "known plaintext" ที่ทำให้ถอดรหัสเฟรมได้

### 4.4 วิเคราะห์

```bash
python3 tools/rs485/analyze.py capture_01.jsonl \
        --expect 1.00 --expect 38.44 --expect 5.00 --timeline
```

เครื่องมือจะบอก:
- **ชนิดข้อความ** จัดกลุ่มตามความยาว + ไบต์แรก พร้อมรูปแบบว่าไบต์ไหนคงที่/ไบต์ไหนเปลี่ยน
- **checksum** ทดสอบ `sum8`, `sum8-neg`, `xor8`, `crc8`, `crc16-modbus`, `crc16-ccitt`, `sum16`
  ทุกช่วงข้อมูลที่เป็นไปได้ แล้วรายงานเฉพาะแบบที่ผ่าน **ทุกเฟรม** ในกลุ่ม
- **ตำแหน่ง field** ค้นค่าที่เรารู้ทั้งแบบ BCD และ binary (LE/BE) พร้อมสเกล
- **timeline** เฟรมรอบ ๆ marker → เห็นว่าเหตุการณ์ไหนทำให้ไบต์ไหนเปลี่ยน

### 4.5 สิ่งที่มักเจอในโปรโตคอลบอร์ดจีน (ใช้เป็นสมมติฐานตั้งต้น — ต้องยืนยันด้วยการดักฟัง)

| ลักษณะ | ค่าที่พบบ่อย |
|---|---|
| Baud / framing | 9600 8N1 (รองลงมา 4800, 19200) |
| รูปแบบ | Master-poll: controller ถามทีละ address, ตู้ตอบ |
| Header | `0x02` (STX) หรือ `0xAA` / `0x55` / `0xFA` |
| Trailer | `0x03` (ETX) หรือไม่มี |
| ตัวเลข | **BCD** (เช่น ลิตร 1.00 → `00 00 01 00`) มากกว่า binary |
| Checksum | sum8 หรือ xor8 ของ body (CRC16 พบน้อยกว่า) |
| Address | 1 ไบต์ ตั้งจาก DIP switch หรือเมนู setup |
| ฝั่ง A/B | บางรุ่นแยกเป็น 2 address, บางรุ่นใช้ address เดียวแล้วมี field nozzle |

**คำสั่งที่ต้องหาให้ครบ:**
`อ่านสถานะ` · `อ่านยอดขายรายการล่าสุด` · `อ่าน totalizer` · `authorize (อนุญาตจ่าย)` ·
`preset by amount` · `preset by volume` · `stop/cancel` · `set price`

## 5. ขั้นที่ 2 — Active probing (มีขั้นตอนกันพัง)

**ทดสอบบนตู้จ่ายที่ปิดใช้งานหรือตู้สำรองเท่านั้น ห้ามทดลองกับตู้ที่ให้บริการอยู่**

1. ทดลองเฉพาะคำสั่ง **อ่าน** ก่อน (status / totalizer) — คำสั่งอ่านไม่ทำให้จ่ายน้ำมัน
2. ต้องมี **สวิตช์ตัดไฟฉุกเฉิน** ของตู้อยู่ในระยะเอื้อมตลอดการทดสอบ
3. ทดสอบคำสั่งเขียน (authorize/preset) โดย **ถอดสายมอเตอร์ปั๊มออกก่อน** ในรอบแรก
   → ดูว่าบอร์ดตอบสนองถูกต้องไหม ก่อนปล่อยให้จ่ายน้ำมันจริง
4. รอบแรกที่จ่ายจริง ใช้ **ถังตวงมาตรฐาน 5 ลิตร** เทียบกับค่าที่ระบบอ่านได้
5. ทุกคำสั่งต้องมี timeout + คำสั่งยกเลิก ทดสอบกรณี "authorize แล้วไม่ยกหัวจ่าย"

## 6. ทางลัด: ให้ PTS-2 แปลโปรโตคอลให้

ถ้า reverse engineering ไม่คืบใน 2–3 สัปดาห์ ให้ตัดใจซื้อ **Technotrade PTS-2**
(รองรับหัวจ่าย 150+ ยี่ห้อ, มี JSON API over HTTP/WebSocket)

**ก่อนซื้อ ให้ทำแบบนี้:**
1. ส่งรูปบอร์ด `ZC-C V1.4` + `ZC-22222` ไปถาม Technotrade ตรง ๆ ว่ารองรับไหม
2. ขอ **trial / ทดสอบก่อนซื้อ** หรือขอรายชื่อโปรโตคอลทั้งหมดที่รองรับมาดู
3. ถ้ารองรับ → งานเราเหลือแค่เขียน HTTP client (2–3 สัปดาห์แทน 2–3 เดือน)

ถ้า PTS-2 ไม่รองรับ ก็ยังใช้ capture ที่เราทำในขั้นที่ 1 ส่งให้เขาเพิ่ม driver ได้

## 7. แผนสำรอง (ถ้า RS-485 คุยไม่ได้จริง ๆ)

| แผน | ได้อะไร | ไม่ได้อะไร | ข้อควรระวัง |

(บอร์ดตู้จ่ายใช้กราวด์คนละจุด — ต่อตรงพังทั้งสองฝั่ง)

## 8. ข้อห้ามทางกฎหมาย (สำคัญกับบอร์ดนี้โดยเฉพาะ)

ในภาพมี **STC U8W-Mini ISP programmer** ติดมากับบอร์ด (ป้าย `ZC-C V1.4 TS 2020-10-05, 400 times`)
เครื่องมือนี้ใช้ **แฟลชเฟิร์มแวร์** ลง MCU ได้

- ❌ **ห้ามแฟลชเฟิร์มแวร์บอร์ดที่ติดตั้งใช้งานอยู่** — บอร์ดนี้เก็บ calibration factor
  ของมาตรวัดและค่า totalizer การแก้เฟิร์มแวร์ = ดัดแปลงเครื่องชั่งตวงวัด
  **โทษจำคุกไม่เกิน 7 ปี ปรับไม่เกิน 280,000 บาท** (พ.ร.บ. มาตราชั่งตวงวัด พ.ศ. 2542)
- ❌ ห้ามปรับ calibration / K-factor เอง
- ❌ ห้ามตัดต่อสาย pulser ที่อยู่ในส่วนผนึกซีล
- ✅ อ่านข้อมูลผ่าน RS-485 = ผู้ผลิตออกแบบมาให้ทำ ไม่ผิดกฎหมาย
- ✅ สั่ง authorize/preset ผ่านโปรโตคอล = ปกติของระบบ POS ตัวมาตรวัดยังนับตามเดิม
- ⚠️ ถ้าเปลี่ยนบอร์ดใหม่ → ต้องให้สำนักชั่งตวงวัดมาตรวจสอบและผนึกซีลใหม่

- [ ] ยอดรวม transaction = `totalizer_end − totalizer_start` **ต่างกัน 0 ลิตร**
- [ ] ทดสอบถอดสาย RS-485 กลางการจ่าย → เสียบกลับ → อ่านรายการที่ค้างได้ครบ
- [ ] ทดสอบตู้จ่ายไฟดับกลางรายการ → บอร์ดจำค่าได้ (มี battery backup) และเราอ่านตามได้
- [ ] จ่าย 5 ลิตรด้วยถังตวงมาตรฐาน → ค่าที่ระบบอ่าน ตรงกับจอตู้จ่าย ตรงกับถังตวง (±50 ml)
- [ ] Authorize แล้วไม่ยกหัวจ่ายภายใน 60 วินาที → auto-cancel ทำงาน
- [ ] Emergency stop สั่งหยุดทุกหัวจ่ายได้ภายใน 1 วินาที

## 11. สิ่งที่ต้องส่งกลับมาให้ผมเพื่อไปต่อ

1. คำตอบจาก True Supply (โดยเฉพาะข้อ 1 กับ 4 ในหัวข้อ 3)
2. ไฟล์ `capture_*.jsonl` จาก sniffer พร้อมตัวเลขจริงที่จอแสดงตอนทดสอบ
3. รูปถ่าย **ใกล้ ๆ** ของ terminal เขียว 4 ขา + silkscreen รอบ ๆ (อ่านชื่อขาให้ออก)
4. รูปเมนู setup ของตู้จ่าย (ถ้าเข้าได้) — หาค่า pump address กับ online mode
5. มี POS เดิมต่ออยู่แล้วไหม ยี่ห้ออะไร (ถ้ามี = ดักฟังได้เลย ง่ายขึ้นมาก)

ได้ข้อ 2 มาเมื่อไหร่ ผมถอดโครงสร้างเฟรมและเขียน driver ให้ได้เลย
